## 3. 四条质控分支

四项检查读取同一条不可变的原始影像描述，诊断分支同时读取原始影像诊断。首版不将 CSC 或 CGEC 建议自动回写为其他分支的输入；接受建议后如需再次检查，产生新的报告版本和运行记录。

### 3.1 诊断一致性质控

输入：原始描述、医生原始诊断。输出：生成参考诊断、诊断中的原文可疑片段、原因、建议及每阶段记录。

仅保留 `diagnosis_thesis`：本地 7B 根据描述生成参考，在线判别模型同时读取原始描述、医生诊断和生成参考，判别并定位诊断片段。第三章采用 DeepSeek-v4-flash/pro 作为判别模型。

生成模型按用户指定路径 `/mnt/mydrive/LLM/paper_models/qwen-7b-lora32-sft` 加载。已确认它是完整 BF16 模型，实际身份与版本记录为该产物；不能因目录名或用户选择就额外声称其 GRPO 来源已经认证。模型来源核对与算力分析分别记录，不因溯源问题擅自更换模型。

判别结果中的诊断可疑片段必须能严格回映射到医生原始诊断，候选建议与原文分别保存。无效结构或非原文片段按未完成处理，不以模型重写诊断替代原文。

参考诊断始终标明为模型生成参照。差异本身不是错误，不以字符串差分直接裁定医生诊断。

### 3.2 第四章字符纠错 CSC

复用 `/mnt/mydrive/LLM/simple-csc` 的医学 CPT、CSC LoRA、C2EC 实现，通过统一 GPU 推理进程中的 CSC 适配器接入。

已找到的约定资产：

- 骨干 `/mnt/mydrive/LLM/models/Qwen2.5-1.5B-medical-cpt`。
- 适配器 `/mnt/mydrive/LLM/models/Qwen2.5-1.5B-medical-csc-lora/checkpoint-600`。
- 上述目录及模型配置文件已确认存在，并已在容量测试中真实加载、完成合成纠错；尚未完成生产服务与连续批量验收。CPT 的最终导出目录保留完整 tokenizer 与权重，移动后的训练 checkpoint-208 不作为推理模型的自动替代。

纯语言概率使用禁用 adapter 的 CPT 主干，提示纠错使用启用 adapter 的分布，独立 KV 缓存；保留加权 Levenshtein 编辑约束，不以普通生成 API 替代 C2EC。论文配置为 beam=2、lookahead=8、alpha=2.5、提示温度 1.5、启用忠实性奖励。

算力检查发现现有默认 `max_length=128`，默认调用只处理前 128 字并回拼剩余原文；这不代表论文历史主实验的实际配置，历史输出已确认存在第 128 字以后的有效纠错，完整启动参数尚未找到。工程适配必须显式设置单次长度上限、确认实际覆盖范围，禁止将未检查的回拼尾部伪装为全文检查。根据用户对短片段处理的要求，首版提出 `csc_punctuation_128_v1`：沿用项目分块工具的标点优先级（句末、分号、逗号/顿号，再硬切）仅按源文分成不超过 128 个 code point 的片段，逐片调用同一 C2EC，按记录的原始区间重组并将编辑回映射到原文；所有原字符恰好覆盖一次，失败片段不回拼后冒充成功。边界处术语和插入/删除效果必须验收。此项是基于现有项目的工程分块策略，不能声称已证明历史实验采用相同处理；现有离线源目标对齐分块脚本默认 192 字，不能直接用于无 gold target 的在线输入。完整长输入已补测至 694 字，但只是容量证据，不是提高上限即可保持纠错效果的证据；具体资源和实验口径核查见算力分析。

输出完整建议文本及确定性对齐的替换/插入/删除编辑，记录源文位置、原片段和新片段。插入为零宽源区间。无错保持原文。分块边界插入归属使用统一半开区间规则：内部边界归右侧片段，原文结尾归末段，重叠冲突标需复核。任何分块失败，CSC 整体执行标失败但保留成功分块及覆盖范围，禁止输出完整通过；整项重试复用已成功片段及相同配置。对超过已验证资源/时限范围的报告明确记为未完成并说明原因，不静默截断，也不把短片段方法宣称为已验证的整篇长文同等效果。

### 3.3 第五章语法纠错 CGEC

复用 `/mnt/mydrive/LLM/LLM4CGEC/medical_validation` 中教师知识、学生条件推理协议。

依据用户的算力讨论，默认目标配置调整为 `cgec_rag_reference_1_5b`：

1. 原始描述最多召回 20 条候选，经 CPU FP32 BGE 重排全部候选后，过滤完全匹配、双向包含和近重复，再取有效 Top-5 表达证据。空证据明确失败，不退为 WoRAG。
2. 在线教师返回有无错误、错误类型、完整参考修正和解释。
3. 原文＋参考修正交给本地 `/mnt/mydrive/LLM/models/Qwen2.5-1.5B`，以论文中的 Reference-only 条件确定性生成完整建议描述。教师的错误类型与解释仍保存并展示，但不强加到本配置的学生输入中。

该学生是独立的 Qwen2.5-1.5B Base 权重，不是 CSC 使用的 Medical-CPT；论文显示它在该教师条件下优于 CPT。不能为节约显存直接复用 CPT 或 CSC LoRA，并宣称仍为同一 CGEC 实验设置。Base 模型使用实验中的完成式示例提示和输出清理，不使用未学习的 chat 模板。

论文教师模型标识为 GPT-5.6-sol/low，既有产物记录 Responses API；实际服务可用性仍待验证。可配置其他可用模型，但必须保存实际标识和配置，不能把替换模型的输出宣称为论文复现。教师四个字段严格校验 JSON 类型与有错/无错一致性；不沿用旧脚本将字符串 false 转为真的宽松转换。教师和学生各阶段输出分别保存。

学生保留实验固定 one-shot 示例、BF16/SDPA greedy、left padding、EOS 和动态输出预算 `min(768, source_tokens+64)`；输入上限 2048 tokens。受资源约束将实验 batch 默认 4 改为 1，记录此调度差异。输入超限显式失败，不继承旧 `truncation=True` 的静默截断。原始 completion 与清理结果分存，接续示例截去，空输出有限重试，未正常结束的截断输出标未完成。CGEC 保持整份描述的语序上下文，不套用 CSC 的 128 字分块；多行原文通过带位置映射的单行模型视图适配，不删除原始记录。

另提供明确选择的 `cgec_rag_teacher_direct` 配置，直接使用教师参考修正；其本身是论文中的独立路径，但不能在学生不可用时静默切换。7B Full EXAM 保留为未来资源更充足时的运行配置，首版不另加载一份 CGEC 7B，也不实现五种条件的实验管理界面。

学生属于测试时教师条件推理，不是已完成 CGEC 专项训练的独立纠错器。教师或学生输出无效时，该分支失败/未完成，不将“返回原文”计为通过。教师判无错时学生仍运行；双方保持原文才为无异常。有错且学生采用相同参考修正为异常；教师有错但学生不改、无错但学生改动、或两份修正不同，均保存分歧并标记需人工复核。医学保护项触发时同样需复核。不能凭修改存在就认定发现了正确错误。

建议范围限定于成分、语序、句式、关联词、否定结构等表达问题。保持部位、数量、大小、方位、病灶属性和阴阳性事实；存在事实改变疑虑时保留建议用于人工审核，并标明“需人工复核”。首版用提示约束、确定性保护项检查和分歧提示控制风险，不承诺存在完整的医学事实等价判定器。SEE 属于有金标准时的离线评价，不在每份业务报告上强制运行。

五组学生条件属于消融实验，业务只执行选定的 Reference-only 一次，不串行执行全部五组。教师二阶段补充实验和第四项定位的条件复核分开：CGEC 首版默认不加入二阶段，保留其既有记录；112 条补充产物中二次复核 2 条、最终参考修正改变 0 条。当前 112 条结果来自对历史 172 条预测按保留 ID/source/target 精确筛选重算，不声称本轮重新调用模型复现实验。

### 3.4 第五章 RAG 原文错误定位

复用 `/mnt/mydrive/LLM/rag-optimizer` 的检索、BGE 重排、可审计定位提示和条件复核逻辑。

- 原始描述召回 20 条，重排、过滤后保留最多 10 条有效证据。
- 第一轮返回原文最短连续可疑片段及解释；无错误时使用明确空结果。
- **仅第一轮未发现错误时，才用同一原文及同一批证据进行第二轮复核**。第一轮有有效片段则直接保留。
- 模型返回的片段必须能够严格回映射到原文。非原文片段不能模糊匹配后冒充准确定位，须重试或记为未完成。
- 首版按论文每轮一个最主要连续片段的输出约定，不承诺穷尽同份报告内所有错误。结果模型允许未来扩展多片段，但不能改变论文分支的语义。
- 定位与 CGEC 是不同输出任务，不强行让定位结果覆盖 CGEC 建议。

论文定位模型为 DeepSeek-V4-Flash，实际可用标识由配置核对。检索不足时使用实际有效证据并记录数量；零条有效证据时标记未完成，不伪装为已成功执行 RAG，也不自动切换无 RAG 基线。

CGEC 按实验的完全匹配、双向包含、近重复条件过滤：仅删除空白后，使用 `SequenceMatcher(None, source, candidate).ratio()` 默认行为，阈值 `>=0.95`。保留全部 20 条重排候选及过滤记录，再分别标记分支的 Top-k 使用情况。定位也应用输入泄露过滤作为工程默认增强，须在配置指纹中标明；它可能与历史审计的具体过滤实现存在差异，不能因此宣称严格数值复现。相似度、归一化及 score 的版本一并固定。

检索只用原始待检描述，不使用人工修正文或金标准。参考报告只用于表达证据；保留独立语料与测试数据隔离。

## 5. 任务执行、失败与恢复

### 5.1 输入和任务

- 单条与批量使用同一处理引擎。批量首版支持 UTF-8/BOM CSV 与 XLSX；要求有“影像描述”“影像诊断”列，额外列与原始行号保留。表头映射可由用户确认，避免按相似名称误判字段。
- 缺失必要列、不可读文件或完全没有可处理行：创建失败并给出原因。个别行缺字段：该行标为无效，其余行继续。四项检查默认都需要的这两列不允许被空字符串伪造。
- 上传创建任务后返回；启动返回 202 和任务 ID，不占住请求等待推理。
- 创建任务即固定四项分支与配置版本。首版默认全选，用户可显式关闭个别分支；修改配置只影响新运行。

### 5.2 调度

每条报告建立四个分支任务，以报告/分支为持久化工作单元。逻辑独立不表示四个 GPU 请求必须同时执行：同一 GPU 资源组默认并发 1，在线 API 全局默认并发 2，服务级限流可配。API、队列 worker、模型进程分别部署。不能以多进程无锁竞争 adapter 或显存。

本机已确认 RTX 3090 24 GiB、Xeon W-2235（12 逻辑 CPU）、约 31 GiB 系统内存。首版算力方案建议为单个本地 GPU 推理进程持有第三章 7B、共享 CPT/CSC LoRA 和 CGEC 1.5B Base，统一互斥调度；Web/Celery 不自行加载权重，不开多个 GPU worker，也不开热重载。显存只保存一份 CPT 骨干，两个 1.5B 初始化版本则必须分别保存。reranker 按用户决定固定 CPU FP32；embedding 沿用当前索引的 bge-m3，并显式固定 CPU，已用 Ollama `num_gpu=0` 验证。在线诊断判别、CGEC 教师与定位不消耗本机生成模型显存。

已经完成三套实际骨干（诊断 7B、CSC CPT、CGEC Base）真实同进程驻留测试：权重约 20.075 GiB，7B 输入 3837 tokens 时 PyTorch 峰值 reserved 约 20.859 GiB，完成时整卡剩余约 2.367 GiB；CSC 完整长输入另以 GPU 权重预留模拟测试。此处“三模型”指三套常驻骨干，与已取消的三专家方案无关。具体上限和连续批处理吞吐仍需按业务长度分布验收，不能外推任意长度/并发。详细证据与限制见 `/mnt/mydrive/LLM/rag-optimizer/output/compute-feasibility-20261015/README.md`。

各模型调用合计最多 3 次尝试，区分超时/限流/网络错误、结构错误和输入错误；瞬时失败退避重试，确定性配置错误不反复调用。每次尝试留有错误码、阶段、时间和可审计的响应记录。

一个分支失败继续其余分支和后续报告；一条报告全失败也不终止整批。配置预检不可用默认阻止新任务启动并返回分支状态，用户可以修复配置或显式关闭该分支，不能静默少跑一项。运行中故障按分支记录，防止 API 中途宕机导致整批丢失。

### 5.3 状态和统计

执行状态与质控结论分开：

- 执行状态：`pending / running / succeeded / failed / cancelled`。
- 有效质控结论：`no_issue / issue / needs_review`；失败、取消、无效输入没有“通过”结论。
- 报告若任一成功分支发现问题，则“发现异常”；若没有明确异常但存在需复核结论，则“需复核”；仅全部选定分支成功且均无异常才“未发现异常”；其他情况标“检查不完整”。额外保留完整性标记，所以“发现异常”也可以同时是部分检查失败。
- 任务完成态：所有选定工作单元成功为 `completed`；既有成功又有失败/无效行/取消为 `partial`；无成功单元且有失败为 `failed`；用户取消且仍有未执行单元为 `cancelled`。成功指完成有效判断，不要求无异常。
- 明确显示总报告数、已完成报告数、异常报告数、需复核数、检查不完整数，以及四项分支的成功/失败数。上述报告计数维度可能重叠，UI 不把它们相加当作总数。
- 不用“没有 ErrorRecord”推导正常，不将跳过/失败计为通过，也不把不同任务的 F1 混为一个准确率。

### 5.4 持久化与恢复

每个分支结果独立提交，Redis 进度可由 MySQL 重建。使用数据库唯一约束、原子认领、运行租约和 worker 心跳避免重复执行已完成的单元；Celery 至少一次投递不等于在线推理恰好一次，故需记录 attempt 和结果去重。

取消任务停止派发新单元，已运行请求在安全结束后保存结果；不能通过终止共享模型进程来取消。服务重启后回收过期租约，将无结果单元重新入队，保留已完成结果。只重试失败分支，原始失败记录仍可查看。用户修改原文或配置后应创建新的运行，不覆盖旧运行。

## 6. 数据与结果契约

最少持久化对象：

- `Report`：不可变原始描述/诊断、业务 ID、来源文件/行号、版本及内容哈希。
- `QualityRun`：单条/批量、选定分支、配置快照、状态、计数、操作者、时间。
- `RunReport`：运行与报告的关联、有效性、汇总结果。
- `ModuleResult`：分支执行状态、结论、原文片段、建议文本、原因、复核记录、耗时与错误。
- `InferenceAttempt`：模型角色、实际模型、输入输出/结构校验、重试记录、tokens/费用（供应商未返回则为空）、时间及请求标识。
- `Evidence`：检索索引版本、证据、得分、过滤与使用情况。
- `ReviewDecision`：接受/驳回/自定义修改/暂缓、审核人、时间、备注；不可覆盖模型原始建议。
- `Artifact`：上传文件、结果文件及校验和。

接口错误约定（2026-10-15用户修订）：自有API的应用错误统一HTTP 200、`status="error"`，在`detail`给出详细错误原因、业务code、失败stage、是否可重试、脱敏异常类型/cause和上下文，附可追踪request_id。成功JSON统一status=success/data封装，执行状态保留在data内；前端必须检查业务status，不可把200当作质控成功。下载失败的JSON也不能保存为XLSX。

代码须分层捕获、分类并抛出异常，保留异常链、脱敏堆栈和阶段/attempt信息；阶段失败仍按既有预算重试、单元失败继续其他行。禁止except-pass、打印后假成功或丢失原始原因；数据库故障无法保存失败状态时继续抛出供恢复机制处理。页面展示可用于维护的detail并可复制request_id，秘密和患者原文不进入普通错误响应或日志。具体协议在后端架构§7.1和实施计划中保持一致。

结果需统一保存模型/adapter 路径或服务版本、prompt 版本、解码参数、检索索引与过滤配置指纹；线上供应商未提供不可变模型 revision 时明确记录这一限制。输出解析失败的原始响应也保留在受控后台存储，页面按需展示，不把完整请求记录打印到普通日志。

原文区间用 Unicode code point 的半开区间 `[start, end)`，验证 `source[start:end] == source_text`。前端使用同一语义的转换工具，不能直接用 JS UTF-16 索引切非 BMP 字符。重复片段需要附位置并验证，只有文本而没有唯一位置时返回候选待复核，不能无条件取第一次出现。

CSC/CGEC 的修改以原文到候选的确定性编辑对齐展示；原文编辑 span 与 RAG 的模型定位 span 分开标识。不同分支的重叠/冲突保留来源；首版不自动合并成最终修正文，不自动写入医生报告。人工确认的修改与原始建议都可导出。

## 7. Web 工作流与样式

导航：概览、单条质控、批量任务、人工复核、运行配置。批量任务列表同时承担历史查询，任务详情展示报告与四项分支状态。单条页面输入原始描述与诊断，默认启用四项，提交后使用同一运行详情。

结果详情展示原文与建议差异、诊断参考、四项结果、失败原因、RAG 证据和阶段记录。定位分支的“查看 Top-10 参考报告”直接按检索排名展示实际检索到的完整报告正文，附报告/文档 ID、来源文件或语料集及记录位置，供参考溯源；不得用模型概括的知识条目替代原始检索内容。按实际有效条数展示，少于 10 条不补齐虚构报告；检索分数和索引版本在有真实记录时展示。先展示结论与原文片段，技术调用详情折叠，页面不堆叠大段方法介绍。不显示虚构的健康评分、准确率或趋势数据。

人工复核操作为接受建议、驳回、编辑后确认、暂缓；影响人工状态和确认稿，不改写模型记录。冲突建议逐项确认。首版免登录，明确使用本地默认操作者，不伪造医生身份；API 保留可替换身份边界。

视觉复用用户已审核的浅色桌面 Web 原型：固定 256px 侧边栏、可折叠为 80px 图标导航、主区相应留白，激活项用稳定背景/描边表达。浅灰背景、白色卡片、蓝色主要操作，圆角克制、间距统一，不添加花哨渐变和动画。页面按钮有焦点与禁用状态，错误信息除颜色外带文字；原文阅读区域控制行宽。根据用户后续明确要求，只设计和验收桌面 Web（1280/1440/1920px），不另做移动端或窄屏抽屉方案。

前端以每任务约 2 秒轮询读取服务端持久状态，任务完成停止轮询。首版无需引入 WebSocket。刷新或关闭页面不影响后台任务。

## 8. 导出

无论全部成功、部分成功或全部模型失败，只要任务已产生报告记录，就提供真实 XLSX 导出，取消任务也可导出已处理结果。

- `报告汇总`：原始字段、报告 ID/行号、各项状态与结论、整体完整性、人工状态。
- `诊断质控 / 字符纠错 / 语法纠错 / 片段定位`：各自的建议、片段位置、依据和实际配置。
- `失败记录`：输入行号、分支、阶段、原因、尝试次数。
- `处理汇总`：总量、各状态计数、开始结束时间和配置版本。

按真实格式导出；外部文本写为文本单元格以防公式执行；不能把 XLSX 内容命名成 CSV。详细模型原始响应通过后台详情/审计文件查看，不默认塞进巨大单元格。

## 10. 验收依据

### 功能与可靠性

1. 同一份合成报告默认创建并真实运行四项检查；四项结果可追溯到原文、实际模型与配置。
2. 单条与批量使用一致输入和配置时生成一致的结构化结果语义，不要求在线模型逐字相同。
3. 一条/一分支的无效 JSON、超时、限流、不可回映射片段、过长输入不会终止其他工作，也不会记为无异常；覆盖首行、中间和末行故障。
4. 浏览器刷新、worker 重启和重复启动请求不丢已提交结果；失败分支可单独重试，取消保留已完成结果。
5. 验证原文不被自动覆盖；重复字串、非 BMP 字符、插入/删除、重叠建议和导出公式文本都有正确处理。
6. 真正浏览器联调上传、进度、四分支详情、人工接受/驳回和导出；旧系统记录不被修改。

### 方法符合性

1. 诊断仅验证论文链路：用户指定的本地 7B 生成参考，在线判别接收原始描述、医生原诊断、生成参考；诊断片段严格回映射到医生原文。
2. CSC 验证 CPT 纯语言分支/adapter 提示分支与论文 C2EC 参数，不能只测试普通补全文本；核对 128 字分块全覆盖、标点优先级、边界词、编辑回映射和部分失败，单独记录分块方法与效果，不能把历史参数未知描述为已复现。
3. CGEC 保存教师三类知识，验证 1.5B Base Reference-only 的固定完成式提示、参数和输出；覆盖教师 JSON 类型/语义校验、空证据、空输出及截断、教师学生分歧，按方法附录验收。教师直出必须显示独立配置名。若未来启用 7B Full EXAM，需另外验证其协议与资源预算。
4. 定位第一轮有片段不调用二轮，第一轮无错误才调用二轮；结构错误不是无错误，二轮失败不标完整通过。
5. 检索保存实际 Top-5/Top-10 证据与过滤记录，不使用目标答案。

### 效果与配置可用性

实现测试使用固定合成样本与受控模拟故障；真实联调使用合成报告，不擅自把既有患者文本发送到云端。论文留出数据的重跑属于单独显式执行的评测，不混入日常健康检查或自动服务启动。

四项真实推理、模型路径和在线凭据均可用后，才称四项联调完成。接口/页面通过但某分支还未接真实模型时，明确报告未完成项，不能用 mock 成功替代。配置预检、结果测试与算法效果评价分别报告，不能宣称新系统已经复现论文历史指标。
